    host a site from a private repo

    To put a static site online without making its source public, publish only the built files: to Cloudflare, or to a second, public GitHub repo for Pages.

    • Free GitHub Pages only serves public repos. A private repo returns "Your current plan does not support GitHub Pages for this repository".
    • Cloudflare Workers with static assets works on the free plan:
      1. Copy the site into a clean folder (no .git).
      2. Add a 3-line wrangler.jsonc: name + compatibility_date + assets.directory.
      3. Run npx wrangler deploy. You get https://<name>.<account-subdomain>.workers.dev.
    • Run wrangler only in a clean folder. Newer wrangler turns pages project create into an automatic Worker deploy of the current folder, which could publish a .git folder. Afterwards, check that /.git/HEAD returns 404.
    • The code stays private, but every file the site serves is public. So publish a build, not the repo. Have a build step write dist/ with only what the page shows. Bundle the content into one minified script, leave out tools, agent files and personal notes, and point assets.directory at ./dist. After deploying, check that the raw paths (/README.md, /brain/…) return 404. kernel does this in scripts/build-site.mjs.
    • Honest limit: anything a browser can show, a visitor can copy. A build stops the site from being a browsable source tree; it can't stop someone copying text they can read.
    • The workers.dev address includes your account's subdomain (here, your email name). A custom domain or a renamed subdomain in the Cloudflare dashboard hides it.

    #Or GitHub Pages, from a second repo

    • Keep the source private. Make a public repo that holds only the builder and its output in docs/. Turn on Pages for main → /docs.
      • Command: gh api -X POST repos/<you>/<repo>/pages -f "source[branch]=main" -f "source[path]=/docs"
      • You get https://<you>.github.io/<repo>/, with no email in the address.
    • Add an empty docs/.nojekyll so files are served as they are. Rename dot-folders (.claude → claude) anyway.
    • The site lives under /<repo>/, not /. Use relative links everywhere, and give 404.html a <base href="/<repo>/"> so it works at any depth.
    • Build only from tracked files (git ls-files), so the site can't show what the repo doesn't hold. Check every internal link after building.

    Used for: kernel (Cloudflare), 2026-10-20. The change vault (GitHub Pages: srvstav/change-vault private → srvstav/change public), 2026-10-21.
