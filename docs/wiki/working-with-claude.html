    working with claude

    Scope before code, give every session a finish line, keep the context clean, run independent work in parallel, and keep local settings out of git.

    #Scope — plan mode

    Claude reads the code without changing anything and hands back a plan for you to check. Read the whole plan. If something is wrong or missing, fix the plan, not the code afterwards. Changing a plan takes minutes. Cleaning up after a bad run takes hours.

    How it fits the vault: brief.md is the plan for the whole project. Plan mode is the plan for one change.

    #Steer — a finish line per session

    /goal <condition> gives the session a condition that has to be true before it counts as finished. /goal clear removes it. Make the condition checkable, like a good Done when: all tests in src/billing pass, and the type checker reports zero errors.

    Good goals often come straight from a slice of the brief's Done when or How we measure.

    #Keep context clean — /compact

    Long sessions drift and get worse. /compact shrinks the conversation so far into a summary. Tell it what to keep: /compact Focus on the --version flag implementation.

    #Repeat — /loop

    Runs a prompt again and again, on a fixed interval or at a pace Claude picks. Good for watching something, like CI or a deploy, or for chipping away at a long checklist.

    #Parallel — worktrees

    A worktree is a separate checked-out copy of the same git repo. Give each agent its own, and several can work at the same time without stepping on each other's files. One worktree per independent task. Only split work that really is independent. Tasks that share files belong in one session.

    #Keep local settings out of git

    .claude/settings.local.json is per-machine (permissions, local paths). Add it to .gitignore before the first commit. If it slips in before any push, rewrite the commit. After a push, just untrack it.
