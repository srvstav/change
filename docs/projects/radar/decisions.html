    decisions

    Newest on top. Never edit an old one — write a new one that replaces it.

    #2026-10-20 — Keys pasted on the page live in memory only

    Why: the user wants Anthropic, OpenAI and Gemini as options without fiddling with env vars. Locally, the page posts the key to radar's own process. radar keeps it in memory and never writes it to disk or returns it. It only accepts JSON posts, which blocks cross-site posts. Instead of: saving keys to a config file. Revisit if: radar is hosted for others. Then keys move to the user's browser (the v2 plan).

    #2026-10-20 — Rank by grounded usefulness; the reader's grades are the ground truth

    Why: the user said the page bragged and the ranking wasn't trustworthy. The judge now rates useful (0–10) on a written rubric anchored on what is actually released (code, weights, demo, paper, announcement). It also writes what / use / checked in plain words, and claims without evidence can't score above 6. The reader grades items Yes / No / Already knew and reports misses. radar eval measures the top-10 hit rate and how often the ranking puts a useful item above a useless one. It sorts each miss into a missing source or a ranking mistake. A learned ranking is adopted only if it beats the current one on grades it never saw. Instead of: an LLM grading the LLM, or hand-tuned weights. Revisit if: the grades say the rubric is wrong (radar eval signal table).

    #2026-10-20 — Free Gemini: 20 requests per model per day, so hop models and judge hourly

    Why: measured: gemini-3.6-flash free tier = 20 requests/day/model. radar now goes down a model list (3.8 → 3.7 → 3.6 → 3.5 → flash-lite) when one is used up, never retries a daily limit, and judges new stories at most hourly on Gemini (RADAR_JUDGE_EVERY_MIN). Instead of: a 10-minute judge loop that runs out of quota by mid-morning. Revisit if: quotas change. For the paid product, free-key users get hourly judging; live judging needs a paid key.

    #2026-10-20 — One model door (llm.py): Anthropic or Gemini

    Why: devs bring Anthropic keys, everyone else can get a free Gemini key. judge and Today now call llm.complete_json(system, user, schema, tier=); provider comes from RADAR_PROVIDER or whichever key is set. Gemini via plain httpx (no new dependency), key in a header, never the URL. Instead of: a second SDK, or an OpenAI-compatible shim. Revisit if: Gemini's structured output rejects our schemas (we strip additionalProperties only).

    #2026-10-20 — Devs are the first lens; radar becomes a system, not a page

    Why: devs fit bring-your-own-key, the user is one, and an MCP server is a natural hook. Other audiences (researcher, founder, investor, team, thinker) come later as lenses on the same engine. Instead of: serving everyone at once (useful to no one), or founders/investors first (need data we lack). Revisit if: devs won't pay but another audience asks to.

    #2026-10-20 — Build the website now, before the 7-day test

    Why: the user chose to go for a paid product. Replaces "Website: after a week of using the engine daily". Instead of: waiting a week. Revisit if: the 7-day misses-vs-noise test (still owed) shows the ranking isn't good enough to sell.

    #2026-10-16 — Lead with "Today" picks, not a feed

    Why: A ranked list still makes you do the deciding. A few picks with a concrete first step is what actually saves the day. Picks favour things you can use (repos, models, demos) that people are adopting fast (stars or likes per day). Instead of: an RSS-style feed as the main view (it stays below as "Everything else"). Revisit if: picks are often unusable (too big, no docs) or miss the day's real headline.

    #2026-10-16 — Skip X.com and Instagram in v1

    Why: No free API. Scraping breaks and breaks their terms. HN and Reddit catch most of what X talks about, a few hours later. Instead of: Nitter mirrors (mostly dead) or the paid X API ($100+/month). Revisit if: the week of testing shows misses that only X had.

    #2026-10-16 — Claude judge is optional; heuristic ranking always works

    Why: The engine must run with no key and no cost. The judge adds "why it matters" and a better impact score when a key is present. Instead of: LLM-only ranking. Revisit if: the heuristic's top 10 is noisy enough that the judge must always be on.

    #2026-10-16 — Python, asyncio + httpx, SQLite

    Why: Fetching is I/O-bound; asyncio runs 15+ sources at once in one process. SQLite gives "seen before" memory with no server. Easy to wrap in a web API later. Instead of: a queue + workers, or Node. Revisit if: sources grow past a few hundred or we need many users.
