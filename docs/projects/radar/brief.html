    radar

    #The announcement

    radar reads the AI frontier so you don't have to. Every few minutes it checks the labs (OpenAI, Anthropic, DeepMind, NVIDIA), the research (Hugging Face daily papers, arXiv, Yann LeCun's new papers), the press (MIT Technology Review), the crowd (Hacker News, Reddit) and AI Explained on YouTube — all at once. It merges the same story seen in many places, ranks it by how much it changes things for someone who builds with deep learning, says in one line why it matters, and shows what people are already building with it. You open one page and you are caught up.

    #Problem

    The field moves daily. Keeping up means checking 15+ sites by hand, and you still miss things or learn late. Missing a big release feels bad and costs time. Every developer, researcher and builder in AI has this problem; most cope with X feeds and luck.

    #Insight

    The signal is not any single source — it's agreement across sources. A thing that shows up on a lab blog, then HF papers, then HN and Reddit within hours is real. Counting that echo, plus a model judging impact, beats any one feed. Fetching is cheap and parallel; judgment is the hard part.

    #Done when

    • One command prints a ranked digest of the last 24h from 15+ sources in under 30 seconds.
    • A watch mode notifies within one poll (≤10 min) of a story crossing the bar.
    • Over one week, the user misses nothing they later wish they'd seen (checked against their own X/HN habit).

    #How we measure

    Each morning for 7 days: compare radar's top 10 to what the user found on their own. Count misses (big things radar missed or ranked below 10) and noise (top-10 items the user didn't care about). Target: 0 misses, ≤3 noise.

    #Simplest version

    CLI. Concurrent fetchers → merge by URL → heuristic score (source weight, engagement, cross-source echo, topic, recency) → optional Claude judge → Markdown digest + SQLite memory of what's been seen.

    #Time box

    v1 engine: one session. Website: after a week of using the engine daily.

    #Riskiest assumption

    That a heuristic + one LLM pass can tell "game-changing" from "loud". Test: run for 3 days and grade the top 10 by hand.

    #Not doing

    • X.com and Instagram in v1: no free API. X's paid API can be a later source.
    • A website before the engine earns daily use.
    • Full-text scraping of articles.

    #Design

    sources (async, parallel, each isolated with timeout + retry)
  → merge (canonical URL; arXiv id == HF paper)
  → score (heuristic) → judge (Claude, top N, optional)
  → reactions (HN + Reddit search for what people made with it)
  → store (SQLite: first seen, notified) → digest (terminal, .md, .json)

    #v2 — from a page to a system (2026-10-20)

    One shared engine, many lenses. The engine fetches, merges, ranks and judges once for everyone. Each lens (dev, researcher, founder, investor, team, thinker, wildcards) is a profile + prompt + signal weights on top. The moat is a knowledge graph with time: entities (models, labs, papers, repos, people, companies) and how they change, so radar can say what changed and why it matters to you.

    First lens: devs. "What can I use today, and does it touch my stack?" Bring-your-own Anthropic key, or a free Gemini key. The personal brief is written in the user's browser, so the key never reaches us.

    Outputs, in build order: live feed → live brief → alerts → lenses → entity graph → Ask (cited answers) → MCP server + API → Team (seats, Slack) → weekly memo.

    Tiers: Free (hourly snapshot, own key) · Pro $5–8/mo (live, alerts, all lenses) · Team $15/seat · API/MCP by usage. INR first via clible-pay; USD once Razorpay approves international.

    Done when (v2): a stranger pays for Pro, and still has it on after 30 days.
