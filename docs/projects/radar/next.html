    radar: next session start here

    The compressed state of the 2026-10-20 session (radar v2 + sketch + kernel hosting). Read this, then projects/radar/state and the top of projects/radar/log.

    #What exists now

    radar: what's new in AI that you can use today, ranked by usefulness, with what's proven versus only claimed.

    • Live demo: https://srvstav.github.io/radar (public repo srvstav/radar, local ~/code/radar-site; a snapshot, refreshed by hand).
    • Engine: private srvstav/radar-engine, local ~/code/radar. Last commits: 164e6b2 (README line), 174ac9c (README redesign), e96ec42, 94e627a.
    • Running on this Mac: the launchd agent com.srvstav.radar at http://127.0.0.1:8788. It starts at login and restarts if it stops. The key is in the Keychain (Gemini), provider in ~/.radar/settings.json, log in ~/.radar/serve.log.
    • radar is a global command (uv tool install --editable ~/code/radar): radar start | stop | key | eval | run | sources | serve.
    • 41 tests pass (uv run pytest -q).

    sketch: live at https://srvstav.github.io/sketch. Its README opens with the live link plus one plain line (0cfe8c5).

    kernel: private repo srvstav/kernel, not cloned under ~/code (clone it: gh repo clone srvstav/kernel ~/code/kernel).

    • Live: https://kernel.ayushsrivastav248163264.workers.dev, a Cloudflare Worker with static assets.
    • Publish with node scripts/build-site.mjs && npx wrangler deploy. Only dist/ goes online: the page, one minified script with the notes bundled in, and the CSS. The tools, agent files and the personal notes (taste, journal) stay private. Raw paths return 404 (verified). Commit 3e23ddf.

    #How radar works now (the parts that matter)

    • llm.py: one JSON call for Anthropic, OpenAI or Gemini. Gemini's free tier is 20 requests per model per day, so it hops down a model list (3.8 → 3.7 → 3.6 → 3.5 → lite), never retries a daily 429, and rates new stories hourly.
    • judge.py: a usefulness rubric anchored on evidence (code, weights, demo, paper, announcement), plus plain what / use / checked. Claims without evidence can't score above 6. A repo or weights radar finds itself overrides the model's evidence guess. Old verdicts are kept until re-rated (this fixed Harness2 vanishing).
    • Rating loop: Useful / Not useful / Knew it, plus missed links on the page. radar eval gives the top-10 hit rate, sorts each miss into a missing source or a ranking mistake, shows a signal table, and --apply adopts a learned order only if it wins on unseen ratings.
    • Page (radar/web/index.html): Newsreader + Geist, ink masthead.
      • "N things worth your time today".
      • Fact strip: Can you use it today? / Is it proven? / Who's paying attention.
      • Copy step + Open.
      • Views: Most useful / Usable today / Important, little attention / Unusual.
      • Sidebar: AI model (key goes to the Keychain), ratings, missed something, sources.
    • keys.py (Keychain) and autostart.py (launchd, picks a free port, checks it's radar answering).
    • AI Explained: falls back to the channel's /videos page when YouTube RSS 404s. Window: 72h.

    #Open, in order

    1. Rotate the Gemini key. It was pasted in chat. Delete it in AI Studio, then radar key gemini.
    2. Rate 20+ items on the page, then radar eval. Until then the ranking is unmeasured.
    3. Stop the stale foreground server on :8791 (Ctrl-C in its terminal). :8787 is the say server; leave it.
    4. kernel's address shows the email name. Rename the workers.dev subdomain or add a custom domain, then update the kernel README and repo homepage.
    5. OpenAI model ids gpt-5 / gpt-5-mini are unverified (RADAR_OPENAI_MODEL).
    6. Demo snapshot refresh is manual (steps in the radar-engine README). Automating it means timed pushes to a public repo, so ask first.
    7. Reddit sometimes 429s from this IP.
    8. Next build (the v2 plan in projects/radar/brief): the live stream (SSE, the page updates as news lands), then the paid tier with ~/code/pay (Razorpay KYC and wrangler login are done for Cloudflare; pay isn't deployed yet).

    #How the user wants work done

    • Useful, not bragging. Every word must help the reader. Plain words, no symbols to decode ("12,702 GitHub stars", not "★").
    • Grounded claims only, no marketing overstatement. "Great, not good."
    • They say "push" when they want pushes. Never add Claude co-author or "Generated with" lines.
    • Check visual work with real screenshots (npx -y playwright@latest screenshot …; use the "Pixel 7" profile for phones, because WebKit isn't installed).
    • Durable knowledge goes in this vault: log and decisions, plus a wiki page for each lesson.
