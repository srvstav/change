    claude / skills / continue · updated 2026-10-21

    SKILL

    Several projects run at once, in parallel sessions. "continue" means: find the best next move, not the last thing touched.

    1. Gather (read-only, keep it short). From now.md → Focus, for each project, or only the named one:

      • its projects/<name>/next.md (or the "Resume here" section of an idea), and the newest entry in log.md;
      • git -C ~/code/<name> status -s | head and git -C ~/code/<name> log --oneline -n 3, for unfinished or unpushed work;
      • whether the live: URL in the brief still loads, if there is one (curl -s -o /dev/null -w "%{http_code}").

      Read files in parallel, and only the parts you need. If the files to read across all projects add up to more than ~15, delegate the gathering to the researcher subagent.

    2. Find candidates. Only improvements that are objectively great, meaning there is evidence a stranger could check:

      • something broken or failing that a user would hit (a 4xx/5xx, a failing test, a console error, a bug written in the log);
      • a ? open question that blocks the brief's Done when;
      • a measured gap: speed, size, accuracy or cost, with the number;
      • work that's finished but not shipped (uncommitted, unpushed, not deployed).

      Taste-only polish doesn't count unless the user has said it bothers them.

    3. Rank by impact (moves Done when, or reaches real people) × confidence (strength of evidence) ÷ effort (sessions). Prefer things that unblock other projects.

    4. Show at most 3, as a short table: project · improvement · evidence (file:line, URL, number) · effort. Recommend #1 in one sentence. Ask exactly one question: "Start #1?" Don't change anything before the user answers.

    5. On yes: work on it in the project's code repo. Verify it with a real check (tests, a browser run, the live URL). Then follow /log for that project: update log.md, decisions.md and next.md.

    Rules: never edit a file another session might be editing without checking git status in the vault first. Logs stay append-only. If nothing meets the bar, say so plainly and name the single most useful piece of evidence to gather instead (for example, "record a 30-second clip of duet on your Mac").
